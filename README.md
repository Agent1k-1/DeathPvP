# DeathPvP

Paper 1.20.1, Java 17. Главный класс: `com.agent1k.DeathPvP`.

`/pvp` открывает меню. `/pvp leave` отменяет поиск. `/pvp team add ник` приглашает игрока; `/pvp team accept ник` принимает приглашение; `/pvp team leave` распускает пати. `/deathpvp reload` требует `deathpvp.admin`, отменяет текущие бои и обновляет конфиги.

В `config.yml` минимальное количество подходящих элементов брони по умолчанию равно одному. Алмазные и незеритовые элементы можно смешивать. Проверка повторяется перед телепортацией.

В `arenas.yml` задайте существующий мир, границы и две безопасные точки, затем включите арену. Арены резервируются на один бой. Нужны физические стены и защищённая от разрушения территория: плагин ограничивает перемещение и телепортации участников, но не заменяет защиту мира. По умолчанию пример арены отключён.

В `menus/search.yml` меняются размер, название, слоты, материалы, названия, lore и actions. Доступны `QUEUE:NORMAL`, `QUEUE:DEATH`, `QUEUE:TEAM`, `LEAVE`, `CLOSE`, `CHAT:текст`, `TITLE:текст`, `SUBTITLE:текст`, `ACTIONBAR:текст`. Цвета задаются через `&`.

В `messages.yml` сообщения поддерживают chat, title, subtitle, actionbar. `%time%` — секунды до телепортации, `%player%` — приглашающий игрок.

Интеграция GreatCombat требует заполнения `combat.start-commands` и `combat.end-commands` действительными консольными командами установленной версии GreatCombat. `%player%` заменяется именем участника. Синтаксис API и команд GreatCombat не предоставлен, поэтому команды намеренно не выдуманы. В обычном бою start вызывается однократно, на смертельной арене повторяется каждые refresh-seconds. До настройки этих команд внешний combat-tag не применяется.

Проверка на сервере: создать арену, проверить железную и смешанную броню, поиск 1v1, приглашение и принятие пати, 2v2, отсчёт, смерть и выход участника, запрет телепортов, освобождение арены и reload. Сборка и запуск не выполнялись по требованию заказчика.

Сообщения используют списки actions: `armor:`, затем `  - '[message] &cТекст'`. Поддерживаются `[title]`, `[subtitle]`, `[actionbar]`; title и subtitle показываются вместе. В меню тот же синтаксис, включая `[queue] NORMAL`, `[leave]`, `[close]`. Старые поля сообщений и действия с двоеточием продолжают работать. Для существующей установки замените messages.yml новым файлом или переведите свои тексты в списки, затем выполните `/deathpvp reload`.

Цвета обрабатывает `com.agent1k.utils.HexUtils`: поддерживаются `&a`, `&l`, `&r` и `&#FFAA00` (регистр HEX не важен). Работает в сообщениях, actions, заголовках меню, названиях предметов и lore. Пример: `'[message] &#FFAA00Привет &fигрок!'`.

Кликабельные приглашения используют `[click] текст | /команда | подсказка`. Несколько кнопок в одной строке разделяются `;;`. Action доступен и в сообщениях, и в меню; поддерживает HEX. Клик выполняет команду от имени игрока. Приглашение проверяется повторно при принятии или отказе: старые кнопки не принимают чужое приглашение. `/pvp team accept ник` принимает, `/pvp team deny ник` отклоняет. Для существующего сервера перенесите обновлённую секцию `invite` и новые секции `invite-missing`, `invite-denied`, `invite-rejected` в messages.yml и выполните `/deathpvp reload`.

В секции `invite` поддерживается короткий action: `'[click] &a✔ Принять | приглашение; &c✘ Отклонить | &7Отклонить приглашение'`. Первая кнопка принимает приглашение, вторая отклоняет; после `|` задаётся подсказка. Имя приглашающего и команды подставляются автоматически. Разделитель кнопок — один `;`. В остальных секциях используется полный формат с командой; прежний полный формат в `invite` также работает. Ручные команды принятия и отказа остаются доступны.

Меню загружает `gui.menu.loader.MenuLoader` из всех `.yml` файлов непосредственно в папке `menus`. `/pvp` открывает `search.yml`. Заголовок задаётся корневым `name`, предметы — произвольными секциями в `menu-settings`. Для своего предмета добавьте уникальную секцию с `name`, `slot`, `material`, необязательными `lore` и `actions`. Например:

```yaml
  help:
    name: '&#FFAA00Помощь'
    lore:
      - '&7Нажмите для подсказки'
    slot: 0
    material: BOOK
    actions:
      - '[message] &eВыберите режим для поиска боя.'
```

Этот блок добавляется внутрь `menu-settings`. `actions: []` подходит для декоративных предметов. `[menu] other` открывает `menus/other.yml`. После редактирования выполните `/deathpvp reload` и заново откройте меню. Настройки меню хранятся в `gui.config.MenuConfig`: `name`, `size` и предметы из `menu-settings`. Старые ключи `title` и `items` не читаются.
